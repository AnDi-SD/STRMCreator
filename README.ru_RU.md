# STRMshelf

Кроссплатформенное настольное приложение для создания и управления медиатекой
`.strm` из внешних источников. Текущая версия работает с TorrServer и рассчитана
на Infuse, но создаёт обычные потоковые ссылки, которые могут открываться
другими совместимыми проигрывателями.

## Возможности

- Импорт локальных `.torrent`-файлов и magnet-ссылок.
- Чтение метаданных torrent без добавления torrent в TorrServer.
- Хранение метаданных torrent и magnet-ссылок внутри базы SQLite: исходные файлы
  после импорта больше не требуются.
- Автоматическое определение фильмов, сериалов, сезонов и номеров серий с
  возможностью ручной корректировки.
- Поддержка torrent, содержащих несколько сезонов.
- Объединение нескольких torrent-источников под одним фильмом или сериалом.
- Перепривязка torrent-источников и отдельных медиафайлов к другому элементу
  медиатеки.
- Создание, обновление, восстановление и удаление управляемых `.strm`-файлов.
- Пересоздание медиатеки после изменения адреса TorrServer или выходных
  каталогов.
- Поддержка локальных каталогов, сетевых UNC-путей Windows и подключённых
  сетевых каталогов.
- Открытие фильма, отдельной серии или всего сезона в проигрывателе по умолчанию.
- Открытие, создание, перенос и резервное копирование активной базы SQLite.
- Интерфейс на английском и русском языках.

STRMshelf не скачивает видео. Получение метаданных по magnet-ссылке работает
через DHT и трекеры, требует наличия активных раздающих и может занять несколько
минут.

## Требования

- Windows 10 или новее, Linux либо macOS
- [.NET 10 SDK](https://dotnet.microsoft.com/download) для сборки из исходников
- Доступный экземпляр TorrServer
- Системная библиотека `sqlite3` в Linux и macOS

## Запуск из исходников

```shell
dotnet restore
dotnet run --project src/STRMshelf.App
```

При первом запуске откройте **Настройки** и укажите адрес TorrServer, а также
отдельные выходные каталоги для фильмов и сериалов.

## Сборка

Сборка и тестирование всего решения:

```shell
dotnet build STRMshelf.sln -c Release
dotnet test STRMshelf.sln -c Release --no-build
```

Создание автономного однофайлового приложения для Windows x64:

```shell
dotnet publish src/STRMshelf.App/STRMshelf.App.csproj \
  -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true \
  -o artifacts/release/win-x64
```

Для публикации под другую платформу замените `win-x64` на подходящий
идентификатор среды выполнения .NET.

Готовые пакеты для Windows, macOS и Debian доступны на странице
[Releases](https://github.com/AnDi-SD/STRMshelf/releases).

## Хранение данных

По умолчанию база данных хранится в каталоге локальных данных текущего
пользователя:

```text
STRMshelf/library.db
```

Расположение базы можно изменить в настройках. Небольшой файл `config.json`
рядом с базой по умолчанию хранит только путь к активной базе и выбранный язык.
Файлы баз данных и WAL, результаты сборки и локальные настройки IDE исключены
из Git.

Приложение удаляет только те STRM-файлы, которые зарегистрированы в базе как
управляемые. Другие файлы в каталогах медиатеки оно не затрагивает.

## Структура проекта

```text
src/STRMshelf.App             Интерфейс на Avalonia
src/STRMshelf.Core            Распознавание torrent и доменная логика STRM
src/STRMshelf.Infrastructure  SQLite, magnet-метаданные и синхронизация файлов
tests/STRMshelf.Tests         Модульные и интеграционные тесты
```

## Локализация

Строки интерфейса хранятся в файлах:

```text
src/STRMshelf.App/Localization/Strings.resx
src/STRMshelf.App/Localization/Strings.ru.resx
```

Чтобы добавить язык, скопируйте нейтральный файл ресурсов в
`Strings.<culture>.resx`, переведите значения и добавьте культуру в
`LocalizationManager.SetLanguage`.

## Разработка

Изменения следует вносить в соответствующий проект и сопровождать тестами, если
они затрагивают разбор torrent, распознавание, базу данных или синхронизацию
файлов. Перед созданием pull request выполните:

```shell
dotnet test STRMshelf.sln -c Release
dotnet format STRMshelf.sln --verify-no-changes
```
